# Blind MCP research round 3, October 3, 2026

Decision: test the released service with ten expert research personas, audit every answer by an independent route, fix each defect at the layer that owns it, and ship one merged push and one container release only after the built image passes the retained controls locally and the deployed service passes them again. Data that was wrong in the published Parquet is repaired by the transform that produces it and republished on its own schedule; a server caveat does not substitute for that.

The decision rule for every finding: reproduce it independently (fresh SQL over the pinned Parquet, then the publisher's own record), locate the owning layer in the code and in the data, state a publisher limit instead of repairing it, and require RED tests before GREEN. A no-tools reviewer then challenged every proposed fix before implementation; the changes it blocked are recorded below as design recommendations, not as work half done.

## Research results

Ten personas, all run at the same model tier, drafted after surveying every table the live `list_sources` reported. Each had never seen the source code or earlier findings. Every persona answered its question; none hit a tool error that was not its own SQL, none timed out. Ten independent auditors re-derived each headline by fresh SQL over the same publication pins and spot-checked identifiers at the publisher.

## Root causes and repairs

Five read-only scouts traced the issues by layer. Declared metadata held the most root causes (12), then the publisher as limits to state (9), acquisition in the source package (7), spicy-regs transforms (7), the server and relationship views (5), publication (1) and the release coupling (1). Two findings were the personas' own.

| Failure or risk | Change | Decisive check |
| --- | --- | --- |
| Six personas read "its meaning and source grain are described by this view" on 822 of 1,381 relationship-view columns | A view column inherits a dependency's dictionary meaning only when its SQL projects that column unchanged (walked through DuckDB's serialized plan at install); every residual column is described by its owner; the fallback sentence is gone | 111 of 111 views, 0 fallback strings; the six RED describe cases pass; `description: None` where nothing is known rather than prose |
| Stale measured facts in coverage prose; coverage kinds chosen by hand; a lint blind to restated measurements | The lint refuses an entry's own `measured_on` restated as coverage, thousands-separated counts in any unit and unanchored counts in `data_quality`; an `Empty` kind is derived from the pinned index under `check --source r2`; 70 wording replacements across about 20 tables | RED: 11 hermetic and 4 live failures before the rewrite; the regenerated catalog is reproducible offline; `financial_changes` declares what it is |
| Oversized replies lost rows for three personas; `describe_table` repeated whole ledgers and join SQL | `list_sources` carries pinned row counts; `describe_table(detail=False)` omits join measurements and ledger statements and names what it omitted; `query_sql(max_cell_chars)` cuts long cells with an honest `truncated_cells` list | `bill_versions` describe 24,600 to 11,649 bytes; a 25-row `committee_meetings` reply 204,218 to 66,586 bytes at 500 characters; truncation is declared, never silent |

| Laws run aborted on a keyless OLRC 403; unavailable laws carried no attempt time | The refusal is journaled (`table3-bulk-refused`, `access-refused`), the family still publishes, the run exits non-zero after publishing; the capture time rides on `unavailable` and `request_failed` rows | RED on the abort and on the dateless row; the next scheduled laws run publishes while the refusal persists |

The reviewer blocked three proposals and changed six. A title-stated Register number does not identify a copy (existence is not identity); a slug-plus-size printing kind is a heuristic on a heuristic; pairing through procedural printings depends on that kind. A tuned 30-day anchor window became the windowless rule above. Inheritance by column name alone became inheritance by SQL lineage. Each is recorded with its measurement in the run directory.

## Verification boundaries

The merged consumer passed its full gate: dictionary generation with no diff, lint, type check, dictionary check over 155 tables, 4,773 tests, strict documentation build, Worker tests and dry run. The built image passed the release binding: 72 FEC views compatible with the prior release's output membership, SQL, dependencies, population, as-of and evidence generations unchanged; the wrong-image, wrong-policy, missing-parent, advanced-parent, missing-receipt and old-query-generation controls each disable all 72 views. The local container then replayed the 65 retained controls, 17 new positive cases drawn from the persona logs, and 9 RED cases; the deployed service replayed them again.

Three RED cases stay red on purpose until their data lands: the comments fill, the amendment-vote bill link and the Senate bioguide fill. Their code is merged; the data moves on the publication schedules named below. The amendment-vote link also needs the source package's vote matching, which is on a bills-lane branch.

Publisher spot-checks support selected Senate roll calls, Congress.gov meetings, GAO letters, GovInfo law packages and regulations.gov comment records. They do not certify whole populations. Two publisher changes were observed during the round and are not bypassed: the House Clerk's legacy roll-call index pages answer 404 since 2026-10-02 while the roll XML files still answer 200, so no votes publication can run until the source lister follows the Clerk's current site; the OLRC Table III bulk zip answers a keyless 403, which the laws run now journals.

Per-call latency is not visible to a persona behind the MCP client, so slow calls cannot be counted for this round; no persona reported one. Three replies were spilled to files by the client harness; the reply-boundary changes above are the response, and wire size does not establish token consumption.

## Remaining limits and owner handoff

Stated limits, not defects: the FR API omits RINs on about 38% of Rules each year since 2018; GAO decisions carry no agency field and closed recommendations are absent; the citator resolves only decisions with a reporter citation; no transcript exists yet for September hearings; `organization` is never filled for 63 agencies at the publisher; member party affiliations record only mid-term switchers; finals without an observed proposal are outside the survival population; Senate expenditure reports are read to page 80 of about 1,300.

Owner decisions deferred from this round: a cluster-level court citation table; a bytes-scanned alternative to the refused EXPLAIN; a companion RIN occurrence view and a dated `roll_call_party` view; a lifecycle cohort window and department roll-up; whether the FEC consumer identity should hash the whole package (today any package change invalidates it, so every server fix is an image release); how floor-amendment annotations in engrossed text should be treated by deltatrack; and the printing-kind classification that the blocked pairing fixes depend on.

Bills-lane handoff: spicy-docs branch `chaos/2026-10-03-bills-lane` (tip `c681b77` on `codex/law-text-release`) carries the law-text reader repair measured on all 113 laws (sidenote lines 7,068 to 30, split clauses 12,037 to 0, sections unchanged), six Senate-only vote columns, the amendment-block vote matching fix (simulation 42 to 648 linked), and schema-module wording. Nothing there is merged, released or vendored; the adoption steps spicy-regs owes afterwards are in the handoff.
