# Civic platform reuse review

Checked 2026-10-03. This is a code, schema, public documentation, and license review; no third-party code was executed or adopted. Repository trees and selected files are pinned in `~/Work/corpora/supply-2026-09-02/receipts/scorecards-reuse-2026-10-03/`. Both CIV.IQ and Civitas OpenAPI documents returned HTTP 200 during direct readback. Recommendations below are engineering judgments, distinct from the cited source facts.

## CIV.IQ

1. **Project/API:** [civdotiq.org](https://civdotiq.org/developers), linked to [`civdotiq/civ.iq`](https://github.com/civdotiq/civ.iq/tree/d1c70cf23341bf43d610730fb591349fe3dda29f); inspected commit `d1c70cf23341bf43d610730fb591349fe3dda29f`. Its public [OpenAPI document](https://civdotiq.org/openapi.json) declares `/api/v1` member, bill, vote, district, and committee endpoints.
2. **What solved:** A typed civic API, downloads with source/freshness metadata, cross-domain entity descriptions, and a separately packaged entity resolver. This provides useful implementation examples for identity and attribution. It does not establish publisher-specific congressional scorecard completeness. The [dataset types](https://github.com/civdotiq/civ.iq/blob/d1c70cf23341bf43d610730fb591349fe3dda29f/src/types/dataset.ts) explicitly separate generated metadata, records, and recorded changes.
3. **Schema/IDs worth reuse:** `bioguideId`, namespaced entity types, `sourceUrl`, `generated`, `recordCount`, and `license`. Its [Bioguide/FEC mapping](https://github.com/civdotiq/civ.iq/blob/d1c70cf23341bf43d610730fb591349fe3dda29f/packages/entity-resolution/src/bioguide-fec-mapping.ts) includes office, district, and `lastUpdated`, but stores a single FEC ID per Bioguide. Preserve our existing historical, multi-ID crosswalk. Its [mesh schema](https://github.com/civdotiq/civ.iq/blob/d1c70cf23341bf43d610730fb591349fe3dda29f/src/lib/mesh/schema.ts) places `voted_on` directly between member and bill; that grain cannot distinguish repeated actions on one bill and should not replace our vote/item identities.
4. **Code/endpoint to integrate:** Evaluate only exact alias/crosswalk portions of [`@civiq/entity-resolution`](https://github.com/civdotiq/civ.iq/blob/d1c70cf23341bf43d610730fb591349fe3dda29f/packages/entity-resolution/README.md), or use `/api/v1/representatives/{bioguideId}` as a separately attributed comparison. Its [methodology](https://github.com/civdotiq/civ.iq/blob/d1c70cf23341bf43d610730fb591349fe3dda29f/packages/entity-resolution/METHODOLOGY.md) includes fuzzy committee and contributor matching; those rules do not meet scorecard V1's exact-only resolution requirement. Do not acquire Congress again through this service.
5. **License/access constraints:** The pinned repository [LICENSE is Apache-2.0](https://github.com/civdotiq/civ.iq/blob/d1c70cf23341bf43d610730fb591349fe3dda29f/LICENSE), while the separate package [LICENSE is MIT](https://github.com/civdotiq/civ.iq/blob/d1c70cf23341bf43d610730fb591349fe3dda29f/packages/entity-resolution/LICENSE). The live developer page/OpenAPI still label the platform MIT. Use file/package-specific licensing and resolve that mismatch before copying broader platform code. Public API documentation says no key and 60 requests/minute for `/api/v1`; no service account was created.
6. **Recommended SpicyDocs/SpicyRegs role:** SpicyRegs comparison and dictionary design reference; optional exact crosswalk evaluation after provenance review. **Schema impact:** retain our separate source member identity, resolved Bioguide, historical terms, and roll/action grain. Add no source table from this review. Dataset-level freshness and record counts are useful documentation fields, but cannot substitute for complete-edition evidence or historical retention.

## Civitas

1. **Project/API:** [`kamoras/civitas`](https://github.com/kamoras/civitas/tree/3747dcc51f404ef85f0096583a44f520056342c5), official site [civitas-research.org](https://civitas-research.org/developers), inspected commit `3747dcc51f404ef85f0096583a44f520056342c5`. This is the U.S. civic score platform, not similarly named municipal software. Live [OpenAPI](https://civitas-research.org/api/public/v1/openapi.json) documents `/api/public/v1`.
2. **What solved:** A public read API for the platform's own representation scores, sub-scores, rankings, historical scores, and member records. Its [public route implementation](https://github.com/kamoras/civitas/blob/3747dcc51f404ef85f0096583a44f520056342c5/backend/app/api/public.py) implements pagination and shares score computation with the application. These are Civitas-published analytical scores, not a collection of other organizations' ratings.
3. **Schema/IDs worth reuse:** The [response schemas](https://github.com/kamoras/civitas/blob/3747dcc51f404ef85f0096583a44f520056342c5/backend/app/schemas.py) provide `entries/total/page/perPage/totalPages`, `siteUrl`, chamber rank, numerical dimensions, and per-dimension confidence. Public member IDs are publisher slugs; `bioguide_id` exists in its [database models](https://github.com/kamoras/civitas/blob/3747dcc51f404ef85f0096583a44f520056342c5/backend/app/models.py) but is absent from the inspected public profile schema. `ScoreSnapshot.algorithm_version` distinguishes formula changes from behavior changes, but the public history schema omits that version.
4. **Code/endpoint to integrate:** A future explicitly attributed Civitas publisher adapter could read `/senators`, `/representatives`, and `/{id}/history`, reconciling every page against `total`. Inspect [`score_calculator.py`](https://github.com/kamoras/civitas/blob/3747dcc51f404ef85f0096583a44f520056342c5/backend/app/pipeline/analyze/score_calculator.py) for versioned methodology design, not as a replacement for published score values. No source qualification or API-to-deployed-formula binding was established here.
5. **License/access constraints:** Repository [AGPL-3.0](https://github.com/kamoras/civitas/blob/3747dcc51f404ef85f0096583a44f520056342c5/LICENSE); preserve the distinction between invoking an API and copying its implementation. Public endpoints require no account/key and share a documented 60 requests/minute/IP limit with MCP. We inspected the spec without downloading the member corpus. API access alone does not establish a separate grant to redistribute all returned normalized data.
6. **Recommended SpicyDocs/SpicyRegs role:** Candidate original publisher only if its analytical scorecards enter scope; otherwise a SpicyRegs analysis reference. **Schema impact:** daily historical score observations need explicit observation dates/edition scopes and methodology-version binding, not overwrite by a current score. Existing metrics/components can represent scored and informational sub-scores separately. Publisher confidence must remain a distinct source observation; do not translate it into our resolution confidence. Missing public Bioguide/version fields remain unresolved, not inferred from database code or name slugs.

## Capitol Trace

1. **Project/API:** [capitoltrace.com](https://capitoltrace.com/developers) and official [CapitolTrace GitHub organization](https://github.com/CapitolTrace). Inspected `congress-api` at `62e7b6a963e5ab1369eaca263e76c43efec0cdbb` and `capitoltrace-ui` at `0cbb91bedb85e58f2987c8ac86e4115ff705bc97`. The organization identifies the core platform/backend as private; no open repository for that normalization or score pipeline was verified.
2. **What solved:** The hosted product exposes aggregated congressional intelligence. The open [`congress-api` client](https://github.com/CapitolTrace/congress-api/blob/62e7b6a963e5ab1369eaca263e76c43efec0cdbb/src/client.ts) supplies typed Congress.gov requests and pagination; it is not an open implementation of Capitol Trace's normalized API. The public UI includes a [`SourceLine`](https://github.com/CapitolTrace/capitoltrace-ui/blob/0cbb91bedb85e58f2987c8ac86e4115ff705bc97/src/components/SourceLine.jsx) attribution component.
3. **Schema/IDs worth reuse:** The client preserves [`bioguideId` and historical member terms](https://github.com/CapitolTrace/congress-api/blob/62e7b6a963e5ab1369eaca263e76c43efec0cdbb/src/resources/members.ts). Its [vote types](https://github.com/CapitolTrace/congress-api/blob/62e7b6a963e5ab1369eaca263e76c43efec0cdbb/src/resources/votes.ts) distinguish Congress, session, roll number, source URL, and member position. Those validate our existing identifiers; they supply no new publisher-rating grain.
4. **Code/endpoint to integrate:** No new backend integration recommended for this task: our existing member/bill/vote ingestion already fills this role. `SourceLine` is a potential attribution UI reference. The documented hosted endpoint `/v1/members/{id}/donors` is useful for comparison, but no key was requested and no authenticated data was fetched.
5. **License/access constraints:** [`congress-api` has an MIT LICENSE](https://github.com/CapitolTrace/congress-api/blob/62e7b6a963e5ab1369eaca263e76c43efec0cdbb/LICENSE). UI [`package.json`](https://github.com/CapitolTrace/capitoltrace-ui/blob/0cbb91bedb85e58f2987c8ac86e4115ff705bc97/package.json) declares MIT, but no standalone LICENSE appeared in its inspected tree. Hosted [terms](https://capitoltrace.com/terms/) require an API key and prohibit redistribution of normalized datasets and use to build a substantially similar competing product. The public-code license does not grant hosted-data redistribution rights.
6. **Recommended SpicyDocs/SpicyRegs role:** Documentation/UI reference only for the scorecard work. **Schema impact:** retain source URL, update date, and fully qualified vote identity. No canonical-schema change, source replacement, or hosted-data ingestion follows from this review. The hosted terms are a concrete reason for a blocked/unapproved redistribution disposition, not permission to retain and republish bytes under `full`.

## Sentinel

1. **Project/API:** Sentinel Intelligence at [sentinelintel.org/about](https://sentinelintel.org/about/) directly links [`Sentinel-Intelligence/sentinel-public`](https://github.com/Sentinel-Intelligence/sentinel-public/tree/9c56267387ef5d0978dac6f70afcede9ad71b08a); inspected commit `9c56267387ef5d0978dac6f70afcede9ad71b08a`. This is the congressional influence graph, distinct from Sentinel security/OSINT products and S4RCIV. Its [API page](https://sentinelintel.org/api-docs/) explicitly offers no public API today.
2. **What solved:** Public graph/methodology documentation, query examples, and inspectable receipt verification. Its [README](https://github.com/Sentinel-Intelligence/sentinel-public/blob/9c56267387ef5d0978dac6f70afcede9ad71b08a/README.md) says full ingestion and Neo4j loading remain future releases. Therefore an open reusable ingestion pipeline was not verified, and headline graph coverage was not independently qualified.
3. **Schema/IDs worth reuse:** [Source documentation](https://github.com/Sentinel-Intelligence/sentinel-public/blob/9c56267387ef5d0978dac6f70afcede9ad71b08a/docs/data_sources.md) distinguishes source database, source record ID, ingestion time, and batch; it says provenance coverage varies. Bioguide/CIK/FEC identifiers coexist with vector similarity `SAME_AS` links. The [graph schema](https://github.com/Sentinel-Intelligence/sentinel-public/blob/9c56267387ef5d0978dac6f70afcede9ad71b08a/docs/schema.md) is a conceptual reference, not a complete machine-readable ingestion schema or an exact-only resolution policy.
4. **Code/endpoint to integrate:** Study [`sentinel_canon_v1_verify.py`](https://github.com/Sentinel-Intelligence/sentinel-public/blob/9c56267387ef5d0978dac6f70afcede9ad71b08a/scripts/sentinel_canon_v1_verify.py): canonical payloads, named signing keys, signature checking, and separate set-membership checking. The API endpoint is unavailable; research access requires contacting the publisher, which this review did not do. Do not execute `xrpl_anchor.py` or adopt a blockchain writer for this task.
5. **License/access constraints:** The public [LICENSE is MIT](https://github.com/Sentinel-Intelligence/sentinel-public/blob/9c56267387ef5d0978dac6f70afcede9ad71b08a/LICENSE). Public tooling availability does not imply access to private graph construction or a dataset redistribution grant. Its own [methodology](https://github.com/Sentinel-Intelligence/sentinel-public/blob/9c56267387ef5d0978dac6f70afcede9ad71b08a/docs/methodology.md) says scores are not individually ledger-anchored: graph state is anchored periodically.
6. **Recommended SpicyDocs/SpicyRegs role:** Evidence-review reference for SpicyRegs; keep Rulespec's existing artifact admission and publication mechanism. **Schema impact:** distinguish observed source fidelity, source coverage, content integrity, and factual truth. A hash/signature proves neither completeness nor publisher correctness. Do not add `SAME_AS` fuzzy matches to V1 or represent graph-state anchors as evidence for every rating. No new source table is justified by the inspected material.
