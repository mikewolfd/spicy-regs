## GovTrack advocacy scorecards

- **Project/API:** [`govtrack/advocacy-organization-scorecards`](https://github.com/govtrack/advocacy-organization-scorecards/tree/fa63a2b5326edd4b8835386082c2317627f058ce), inspected commit `fa63a2b5326edd4b8835386082c2317627f058ce` (2021-02-02).
- **What it solved:** A curated collection of published member scores, stored as publisher metadata followed by CSV rows. This is a secondary dataset, not a publisher acquisition framework. The inspected tree has `README.md`, `lint.py`, and publisher files under `scorecards/`; it contains no refresh adapters or source-completeness implementation. [Tree](https://github.com/govtrack/advocacy-organization-scorecards/tree/fa63a2b5326edd4b8835386082c2317627f058ce).
- **Schema/IDs worth reusing:** Publisher name, homepage, original scorecard link, literal period description, rating unit, and the explicitly named GovTrack member ID. `updated` may mean publication **or import** date, so it must not become `published_at_text` automatically. The model holds one integer percentage or letter grade per person; it cannot replace the frozen multi-metric/item/result model. No source-table schema change is warranted. [Format](https://github.com/govtrack/advocacy-organization-scorecards/blob/fa63a2b5326edd4b8835386082c2317627f058ce/README.md).
- **Actual code/endpoint to integrate:** Read commit-pinned `scorecards/*.yaml` metadata for census discovery and retain its original-publisher `link`; use existing `members.govtrack_id` for secondary cross-checks. [`lint.py`](https://github.com/govtrack/advocacy-organization-scorecards/blob/fa63a2b5326edd4b8835386082c2317627f058ce/lint.py) parses the YAML/CSV boundary but rewrites files and pads values; it does not prove publisher completeness or identity uniqueness. Do not use it as the source reader.
- **License/access constraints:** Public raw files are accessible without an API key. No license file or license grant appears in the inspected tree/README; GitHub metadata reports no license. This does not establish redistribution rights for the publishers' ratings or permission to copy project code. [Repository metadata](https://api.github.com/repos/govtrack/advocacy-organization-scorecards).
- **Recommended SpicyDocs/SpicyRegs role:** SpicyRegs census seed and comparison input only. SpicyDocs should still acquire ratings from the original publisher; retain this repository's import timestamp and provenance separately.

## unitedstates/congress

- **Project/API:** [`unitedstates/congress`](https://github.com/unitedstates/congress/tree/8184bcb13160da2389dea4c902de67817db681fc), inspected commit `8184bcb13160da2389dea4c902de67817db681fc`.
- **What it solved:** Official-source bill-status processing, amendments, roll-call parsing, and incremental GovInfo acquisition. These are useful reference implementations for legislative records, not third-party scorecard readers. [README](https://github.com/unitedstates/congress/blob/8184bcb13160da2389dea4c902de67817db681fc/README.md).
- **Schema/IDs worth reusing:** Bill/amendment natural identifiers and separate vote, bill, amendment and member identities. **Compatibility finding:** upstream `h1-119.2025` uses a calendar-year session; SpicyRegs `119-house-1-1` uses an ordinal session. Upstream also accepts older digit/letter session identifiers. A qualified mapping is required; copying the field or ID directly is wrong. Source literals already fit `references_json`; no frozen source-table change is needed. [ID parsing](https://github.com/unitedstates/congress/blob/8184bcb13160da2389dea4c902de67817db681fc/congress/tasks/utils.py#L127-L154), [vote construction](https://github.com/unitedstates/congress/blob/8184bcb13160da2389dea4c902de67817db681fc/congress/tasks/vote_info.py#L12-L63).
- **Actual code/endpoint to integrate:** Reuse local `BillIdentity`, `schemas.tables.bill_id`, `VoteKey`, and `schemas.congress_activity_tables.vote_id` as validated target identifiers. Consult upstream `bill_info.py`, `amendment_info.py`, and `vote_info.py` when checking external identifier dialects. Link against existing `congress_bills`, `amendments`, `roll_call_votes`, `members`, and `member_terms` publications; do not run `usc-run` or add another acquisition path.
- **License/access constraints:** Repository code is dedicated under [CC0](https://github.com/unitedstates/congress/blob/8184bcb13160da2389dea4c902de67817db681fc/LICENSE). Its government-data collectors do not establish third-party scorecard redistribution rights. This research inspected code only and did not reacquire official legislative data.
- **Recommended SpicyDocs/SpicyRegs role:** Identifier/reference guidance for existing SpicyDocs readers; exact joins in SpicyRegs. Keep source and resolved IDs separate, and preserve multiple actions on the same bill.

## unitedstates/congress-legislators

- **Project/API:** [`unitedstates/congress-legislators`](https://github.com/unitedstates/congress-legislators/tree/d5af3d2d2490f8c6532c9490b1f47a76cacca699), inspected commit `d5af3d2d2490f8c6532c9490b1f47a76cacca699`.
- **What it solved:** A maintained crosswalk among congressional person identifiers, plus historical terms and source-stated alternative names. This dataset is already the input to the existing SpicyDocs legislators reader and SpicyRegs members pipeline. [Upstream data dictionary](https://github.com/unitedstates/congress-legislators/blob/d5af3d2d2490f8c6532c9490b1f47a76cacca699/README.md#legislator-data-dictionary).
- **Schema/IDs worth reusing:** `id.bioguide`, `id.govtrack`, `id.lis`, **`id.votesmart`**, term dates/chamber/state/district; retain `other_names` and `bioguide_previous` for exact historical identity resolution. **Concrete schema change:** add optional `votesmart: int` to existing `Legislator` parsing and `members.votesmart_id` as VARCHAR, then enable the `votesmart` exact resolver scheme. The reader, member row shaper/schema, and resolver omitted it at the start of this review; the local implementation now retains and resolves it. At the pinned commit, `id.votesmart` is integer in 519/539 current records and 826/12,231 historical records; the union contains 1,345 distinct values with no observed cross-person duplicate. These are measured dataset coverage figures, not a claim of universal identity coverage. [Current file](https://github.com/unitedstates/congress-legislators/blob/d5af3d2d2490f8c6532c9490b1f47a76cacca699/legislators-current.yaml), [historical file](https://github.com/unitedstates/congress-legislators/blob/d5af3d2d2490f8c6532c9490b1f47a76cacca699/legislators-historical.yaml).
- **Actual code/endpoint to integrate:** Extend existing `spicy_docs/sources/legislators.py` (`_ID_INT_FIELDS`, `Legislator`, `_read_record`) and `schemas/legislator_tables.py` (`MEMBERS`, `shape_member`); use the existing current/historical JSON endpoints already selected by `LegislatorsAcquirer`, then extend `spicy_regs/scorecards/resolution.py`. Do not import upstream [`congress_lookup.py`](https://github.com/unitedstates/congress-legislators/blob/d5af3d2d2490f8c6532c9490b1f47a76cacca699/congress_lookup.py): it is an interactive, current-roster lookup with wildcard matching. Local `interpretation/member_matching.py` likewise uses first-wins collisions and a surname/token-similarity fallback, which conflicts with exact, ambiguity-preserving V1 resolution.
- **License/access constraints:** Dataset and repository carry [CC0](https://github.com/unitedstates/congress-legislators/blob/d5af3d2d2490f8c6532c9490b1f47a76cacca699/LICENSE). The coverage measurement read commit-pinned YAML without publishing source bytes; current/historical SHA-256 respectively `bd32e62b1c89e9585e4ec49df5676563510e9435d779c061ff50139833f73a49` and `9641615f336b3113d6f89152e3441128cbdc3f61ccf87c65da3a015076c78c91`. No API key was required.
- **Recommended SpicyDocs/SpicyRegs role:** Retain the missing upstream field through the **existing** crosswalk pipeline; resolve publisher-supplied Vote Smart IDs against its immutable published rows. Missing IDs remain unresolved and future collisions must preserve all candidates. The scorecard source schema already supports the identifier scheme/value pair.

## Open States

- **Project/API:** [`openstates/openstates-core`](https://github.com/openstates/openstates-core/tree/c0097b1af6c8ecae15777078008b666225ee30cb), commit `c0097b1af6c8ecae15777078008b666225ee30cb`; [`openstates/api-v3`](https://github.com/openstates/api-v3/tree/58696e5e921bbae6afb6d8f4aa693c3eb65837b0), commit `58696e5e921bbae6afb6d8f4aa693c3eb65837b0`; public [API specification](https://v3.openstates.org/openapi.json) inspected on 2026-10-03.
- **What it solved:** Legislative data with jurisdiction/session context, separate sponsorship/action/vote records, named participants that may remain unresolved, and source links. The API primarily covers state legislation; its location lookup also advertises US Congress people, which is not evidence of a federal congressional bills/votes replacement. [API overview](https://docs.openstates.org/api-v3/).
- **Schema/IDs worth reusing:** `ocd-person`, `ocd-bill`, `ocd-vote`, jurisdiction IDs and namespaced alternative identifiers. `VoteEvent` has an organization and nullable bill; `PersonVote` preserves `voter_name` when `voter` is null. These support the present design's separate action occurrences and unresolved source identities; they do not justify converting every scorecard item into a roll call. No immediate source schema change is needed. [Vote model](https://github.com/openstates/openstates-core/blob/c0097b1af6c8ecae15777078008b666225ee30cb/openstates/data/models/vote.py), [API schemas](https://github.com/openstates/api-v3/blob/58696e5e921bbae6afb6d8f4aa693c3eb65837b0/api/schemas.py).
- **Actual code/endpoint to integrate:** No new federal feed. For a separately authorized future state scope, `/bills/{jurisdiction}/{session}/{bill_id}` with `include=votes`/`sponsorships`, `/people`, and `api/schemas.py` provide concrete integration surfaces. `/committees` and `/events` have experimental/coverage qualifications in the live OpenAPI description. The bill routes and joins are implemented in [`api/bills.py`](https://github.com/openstates/api-v3/blob/58696e5e921bbae6afb6d8f4aa693c3eb65837b0/api/bills.py).
- **License/access constraints:** Core/API code is MIT ([core license](https://github.com/openstates/openstates-core/blob/c0097b1af6c8ecae15777078008b666225ee30cb/LICENSE), [API license](https://github.com/openstates/api-v3/blob/58696e5e921bbae6afb6d8f4aa693c3eb65837b0/LICENSE)); this differs from the data's [public-domain dedication unless otherwise noted](https://open.pluralpolicy.com/data/). The [service terms](https://open.pluralpolicy.com/tos/) allow access limits and disclaim guarantees. Data API calls need a key; [`api/auth.py`](https://github.com/openstates/api-v3/blob/58696e5e921bbae6afb6d8f4aa693c3eb65837b0/api/auth.py) enforces account tiers and 401/403/429 refusals. No authenticated data calls were made.
- **Recommended SpicyDocs/SpicyRegs role:** Reuse schema lessons and explicit-source semantics now; reserve API adapters for a future state vertical. Retain existing federal publications and source-evidence infrastructure.

## Open Civic Data

- **Project/API:** [`opencivicdata/python-opencivicdata`](https://github.com/opencivicdata/python-opencivicdata/tree/c089b29a024ceb726765c24f3db792c49fdf8275), commit `c089b29a024ceb726765c24f3db792c49fdf8275`; [specification](https://github.com/opencivicdata/docs.opencivicdata.org/tree/713aa1714902294637d3e419ab5ce24b839eda3a), commit `713aa1714902294637d3e419ab5ce24b839eda3a`; [division IDs](https://github.com/opencivicdata/ocd-division-ids/tree/1ec1eda010addd54412f5491d8d695303189e354), commit `1ec1eda010addd54412f5491d8d695303189e354`.
- **What it solved:** Shared civic identifier conventions and models distinguishing geography, governing organizations, memberships, legislation, and voting events. It is a schema/toolkit, not an authoritative scorecard or maintained federal acquisition service. [Data types](https://github.com/opencivicdata/docs.opencivicdata.org/blob/713aa1714902294637d3e419ab5ce24b839eda3a/data/datatypes.rst).
- **Schema/IDs worth reusing:** Scheme-qualified IDs and the distinction between geographic division and legislative organization. The vote model allows a bill-less motion, unresolved named voter, multiple vote events and source links. These confirm existing source-item/result choices; future committee resolution should name the actual organization, not fabricate a chamber roll call. Geographic IDs alone cannot replace historical district/term evidence. [Vote implementation](https://github.com/opencivicdata/python-opencivicdata/blob/c089b29a024ceb726765c24f3db792c49fdf8275/opencivicdata/legislative/models/vote.py), [ID specification](https://github.com/opencivicdata/docs.opencivicdata.org/blob/713aa1714902294637d3e419ab5ce24b839eda3a/ocdids.rst).
- **Actual code/endpoint to integrate:** Use `opencivicdata/legislative/models/vote.py` as a structural reference; retain explicit OCD identifiers only when a publisher supplies them. Do not add its Django/PostgreSQL model dependency to the source readers or mint OCD identities for unresolved people. No live OCD API dependency was established; the guessed `opencivicdata/ocdapi` repository returned 404.
- **License/access constraints:** Python toolkit code uses [BSD-3-Clause](https://github.com/opencivicdata/python-opencivicdata/blob/c089b29a024ceb726765c24f3db792c49fdf8275/LICENSE); the division-ID dataset explicitly uses [CC0](https://github.com/opencivicdata/ocd-division-ids/blob/1ec1eda010addd54412f5491d8d695303189e354/LICENSE.md). The documentation repository has no detected license, and its [adoption page](https://github.com/opencivicdata/docs.opencivicdata.org/blob/713aa1714902294637d3e419ab5ce24b839eda3a/data/introduction.rst) warns that parts are outdated. Do not transfer a code or identifier-dataset license to third-party source captures.
- **Recommended SpicyDocs/SpicyRegs role:** Preserve source names and identifiers in SpicyDocs; keep entity resolution and historical membership joins in SpicyRegs. The reviewed material supports the present separation and does not require a new federal data ingestion or additional scorecard source table.
