## Replay and required inputs

The private ingestion plan has SHA-256
`4d78be92a7009421967b30bba172d1bd8f30a5f5184def96d26f13f38ef1e3ec`.
The dated replay assessment covers 134 distinct additional source scopes, with
zero publisher network requests. It reconciles all accepted source tables,
capture sequences, parser identities and completeness checks against their
pinned references. Public qualification receipts retain input digests and
counts; source bodies and model observations remain in the private corpus.

The first retained replay completed 82 scopes and then refused a legacy
Peace Action input-key shape. The canonical asset keys were corrected without
changing source or observation bytes. A fresh replay passed the remaining 18
scopes, and another passed the 34 FreedomWorks scopes. The combined assessment

The shared reader lookup now checks required constructor inputs before either
coverage generation or retained replay. It rejects missing assets, conflicting
asset forms and unknown argument names without executing the reader. This
prevents incomplete input plans from advancing the publisher queue.

## Preparation reuse and verification

Preparation checks historical preservation and publisher references inside the
existing verified readback of persisted source receipts. It retains the
assessment instead of rebuilding those same rows a second time. Native prior
inputs use the receipt reader directly. Later generation verification still
reads and validates its own persisted inputs.

The bounded benchmark used 19,047 receipts. The restored rows and six source
hashes remained identical. Full receipt reconstructions fell from four to two;
median boundary time fell from 20.2675 seconds to 9.8453 seconds. These are
measurements of that fixture boundary, not a forecast for full publication.

The consumer full test suite, whole-repository Ruff and Ty checks, and data
dictionary check and regeneration passed with the selected package. Generated
publisher coverage is checked separately after each ledger change.

## Publication boundary and remaining work

Use the existing [preparation and publication procedure](README.md) with the
pinned plan. Require a successful preparation receipt, atomic source-family
publication, downloaded public member verification and hosted MCP readback
before recording any scope as published. Historical rows outside the selected
scopes must remain unchanged; public third-party evidence remains `hash_only`.

Exact member and legislative-item analysis runs in its separate family against
the accepted source generation and existing congressional tables. Live refresh
requires explicitly configured and qualified acquisition inputs. Remaining
candidate publishers and source renditions stay in the generated queue; a failed
URL or an incomplete document does not establish that a publisher is retired.
