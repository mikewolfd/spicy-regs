# MCP server on Cloudflare Containers

Runs the canonical `spicy_regs.mcp_server:build_app` as a Cloudflare Container,
fronted by a Worker — colocated with the R2 bucket, on the vendor that already
hosts the data, cache rule, and DNS.

`npm run check` generates binding types, typechecks and bundles the Worker,
and checks the deployment configuration. The selected container image is
pinned by registry digest. Image qualification and live MCP checks are separate
steps; a Worker dry run does not establish either.

## Why Containers (vs Cloud Run / Vercel)

Heavy analytics wants memory **and** room to spill. Cloudflare's `standard-4`
instance is 4 vCPU / 12 GiB RAM / **20 GB real disk** — the disk is the point:
`SPICY_REGS_TEMP_DIR=/tmp` gives DuckDB genuine disk-backed spill, so a big
aggregation that exceeds RAM completes instead of OOMing. (Cloud Run's `/tmp` is
RAM-backed, so its spill isn't real headroom; Vercel caps memory outright.)

## Files

- `Dockerfile` — the image (canonical server under uvicorn on `$PORT`). Generic.
- `wrangler.template.jsonc` — exact container image, release pins, Durable Object binding
  and `standard-4` instance. Build new images with the repository root as context.
- `worker/index.ts` — forwards `/mcp` to the container; sets the DuckDB/R2 env.
- `start_reader.py` — shared image/Worker entrypoint; checks the selected receipt
  against installed code before replacing itself with the server process.
- `package.json` — `wrangler` + `@cloudflare/containers` + a `check` script.
- `worker-configuration.d.ts` — generated by `wrangler types` (gitignored); run
  `npm run types` after changing bindings.

## Prerequisite: Workers Paid

Containers require the **Workers Paid plan** ($5/mo) — the free plan can build the
image but the push fails with a `401` on `cloudchamber` (Cloudflare's container
runtime). Enable it once per account: dash → Workers & Pages → Plans → Workers
Paid. Everything up to the push works on free (`npm run check`), so validate
there first.

## Deploy

For the established production service, use the explicit production command.
It sets account `174055408ff1560e60601c4d12c561c4`, `mcp.spicygov.ai`,
`https://data.spicygov.ai` and guide `https://spicygov.ai/mcp/` without requiring
shell exports. Supply the qualified image digest and its published matching
FEC receipt on every release; both must use `sha256:<64 lowercase hex digits>`.
The renderer checks the target and refuses conflicting ambient settings before
writing configuration or starting Wrangler. It replaces the template's old pins
with these explicit inputs. This local check establishes configuration consistency;
the image association and receipt qualification remain release prerequisites.

```bash
cd deploy/cloudflare
npm run deploy:production -- \
  --image-digest "$QUALIFIED_IMAGE_DIGEST" \
  --release-sha256 "$PUBLISHED_FEC_RECEIPT_SHA256" \
  --profile spicy-regs-civictechdc
```

Use the existing installed Wrangler and named account login. The command renders
and deploys the same checked config without running generic configuration again.
To render without uploading, invoke `python3 ../../scripts/render_cloudflare_config.py
--production --image-digest "$QUALIFIED_IMAGE_DIGEST" --release-sha256
"$PUBLISHED_FEC_RECEIPT_SHA256"`; then run the installed Wrangler's `deploy
--dry-run --profile spicy-regs-civictechdc` if that release needs a Worker check.

Generic forks keep `npm run configure`, `npm run check` and `npm run deploy`.
Complete [fork setup](../fork-setup.md), install the locked npm dependencies,
and set the fork's account and release pins in `wrangler.template.jsonc`.
`SPICYREGS_DOMAIN` defaults to `spicy-regs.dev`; explicit data URL overrides retain
precedence, and `MCP_GUIDE_URL` remains optional. See [domain setup](../public-domain.md).
These generic commands render the ignored `wrangler.jsonc` and may overwrite a
previous production rendering. `deploy:configured` is the shared internal command;
use `deploy:production` or `deploy` to render the intended target first.

`wrangler` prints a `*.workers.dev` URL; smoke-test the MCP handshake against `/mcp`.

### Qualified FEC views

After the retained FEC data and archive pass their release checks, set
`SPICY_REGS_FEC_RELEASE_SHA256` to the published release receipt's SHA-256 and
`SPICY_REGS_CONSUMER_IMAGE_DIGEST` to the digest of the actual deployed image.
Both use `sha256:<hex>` values and belong in deployment configuration. The
Worker forwards them through the container's
[`envVars`](https://developers.cloudflare.com/containers/examples/env-vars-and-secrets/).

Build the image first, create the receipt with that image identity, then inject
the two pins when deploying that same image. Keep the receipt outside the image
and the generations it references to avoid circular hashes. The server reads
the receipt from the configured data base and checks its exact data, code,
dictionary and policy dependencies. Empty or mismatched pins leave qualified
FEC views disabled. Verify the returned release identities and refusal behavior
against the running service before declaring delivery complete; see the
[FEC release checks](../../docs/fec-delivery-plan.md#compatible-release-and-deployment-checkpoint).

The Worker embeds `start_reader.py` as the SDK entrypoint override, so the same
startup check runs even when Cloudflare starts the previous image during rollout.
It uses the existing bounded receipt loader and actual installed-code/package
measurement, under a cooperative 60-second startup bound, before `exec` starts
uvicorn. A mismatch or unavailable receipt starts no MCP server. Cold-start
failure returns 503 without forwarding or replaying the user's request. Both
release pins absent retain unqualified local/fork serving; partial pins refuse.

This prevents serving an internally incompatible release; it does not make
Cloudflare deployment atomic or promise zero downtime. The default scheduler
[activates the Worker before replacing containers](https://developers.cloudflare.com/containers/configuration/rollouts/).
An already-running prior process keeps its prior startup configuration. The new
guard cannot retroactively change a legacy process; the actual-runtime check
before publication covers that transition. Retain the compatible prior image,
receipt and Worker configuration for rollback if replacement does not become
ready. No automatic deployment, request replay or restart loop is added.

For the next required consumer release, dispatch **Build and publish MCP reader
image** (`build-mcp-image.yml`) with the ref's full commit as
`expected_source_sha`. Configure the dedicated registry credential described in
[fork setup](../fork-setup.md#mcp-image-registry-credential) first. A missing
secret or account mismatch refuses before installation; registry authentication
must succeed before Docker builds. The workflow uses the locked Wrangler CLI
to obtain one temporary push/pull credential, then Docker publishes the same
checked image to `registry.cloudflare.com/<ACCOUNT_ID>/spicy-regs-reader`.
Temporary credentials stay outside the retained evidence and are removed at
job completion. The 30-minute credential covers the job's 25-minute limit.

The Dockerfile runs native reader fixtures and locked package checks. The
workflow also checks the installed packages and records `runtime_consumer`
inside that image, then reads the pushed registry manifest by digest and
requires its config digest to equal the checked image ID. The
`mcp-reader-image-<COMMIT>` artifact retains source commit/tree, build-input
checksums, build/push logs, image inspection, installed runtime identity and
`registry-association.json`. That association binds the registry digest to the
source, `uv.lock` and measured consumer. Keep this small artifact with the
release evidence before its 14-day expiry. The normal route needs no image
archive download or workstation relay; existing archives remain recovery
evidence. See [Cloudflare image management](https://developers.cloudflare.com/containers/guides/image-management/#push-images-with-ci)
and [Docker registry publication](https://docs.docker.com/reference/cli/docker/image/push/).

Registry publication does not deploy the Worker or qualify a serving release.
Use the successful association's immutable `registry_image` and `consumer` to
construct the matching release receipt. Publish and verify that receipt before
passing its digest and the image digest to `deploy:production`. For generic forks,
update all three template values: `containers[].image`,
`SPICY_REGS_CONSUMER_IMAGE_DIGEST` and `SPICY_REGS_FEC_RELEASE_SHA256`. Verify
the actual provider image selection and bounded live MCP release checks after
deployment. Prepared datasets still need their reader checks.

Deploying existing configuration reuses its image even when local Python source
has changed. Retain the prior registry digest, matching release receipt and
Worker configuration/version. Roll back by selecting that compatible set and
rechecking the running service; do not delete its registry image. If a workflow
fails after pushing, inspect its retained push/manifest evidence before any
retry. A failed or absent association is not an accepted image release.

If a rollout leaves the native connection claiming to run while its port reports
that the container is stopped, the Worker confirms that contradiction with a
short HEAD probe and resets the Durable Object. The next request reconnects;
the failed request is never replayed. Ordinary application errors pass through.
The reset can interrupt concurrent requests, so it applies only to this exact
native error. `npm test` exercises the SDK boundary with mocks; public checks
must still establish actual Cloudflare recovery.

### Catalog and public reads

The MCP reads the configured bucket's published Parquet, including the comments
mirror. Keep `R2_CATALOG_URI` and `R2_CATALOG_WAREHOUSE` empty on this Worker.
Complete catalog configuration is refused: its dynamic file access has not been
qualified against the public SQL server's selected-file restrictions.

Iceberg remains the ingestion and update store. The
[2026-09-27 comparison](../../docs/research/mcp-chaos-2026-09-27.md#iceberg-decision)
matched the current comments catalog snapshot to the published mirror receipt
and public objects. Direct catalog access showed no freshness benefit in that
measurement. ETL credentials belong to the ingestion workflows, independently
of this public serving configuration.

## Tuning

`instance_type`, `sleepAfter` (idle → scale to zero), `SPICY_REGS_MEMORY_LIMIT`
(keep under the instance RAM so heavy queries spill to disk rather than being
killed) and `SPICY_REGS_TOOL_CONCURRENCY` (tool calls run at once, on worker
threads) are the knobs. `max_instances` is not a concurrency knob: the Worker
calls `getContainer` without a name, so every request reaches one container.
More instances would each run their own cold build against the bucket.
Re-measure after changes.

### Separate MCP connection guide

`MCP_GUIDE_URL` optionally redirects browser GET/HEAD requests for `/` to an
absolute HTTPS guide URL. Leave it unset to keep the upstream container landing
page. `/mcp` and `/mcp/*` still go to the MCP server without a redirect, including
POST requests. The guide remains accessible while data is unavailable.

The production command sets `https://spicygov.ai/mcp/`, maintained in
[mikewolfd/spicygov](https://github.com/mikewolfd/spicygov). Generic forks must
export their guide URL when desired; GitHub repository variables are not
automatically inherited by local Wrangler commands. Deploy the guide before
enabling the redirect.

## Explicit local delivery operations

Use `local_delivery.py` to capture the current publication index before preparing
a necessary local release, then deliver its qualified image and data. It replaces
task-specific Python copies of the capture, push, publication and bounded readback
callers. It does not build, bind FEC metadata,
select a provider image, deploy, or sequence those steps. Keep using the existing
accepted-input binder and `deploy:production` with the named
`spicy-regs-civictechdc` profile. Account, bucket, registry and public endpoints
remain the established production targets.

Run from the exact clean source checkout with its existing locked Python
runtime. Supply one reviewed JSON input. All file references below are absolute;
`pin` means `{"path": "/absolute/control.json", "sha256": "<exact hex SHA256>"}`.
Credential values never belong in this input; `env_file` names the existing
private R2 credential file.

The initial read-only capture needs only `source`, before image or serving
controls exist:

```json
{"source": {"commit": "<exact commit>", "tree": "<exact tree>"}}
```

```sh
python deploy/cloudflare/local_delivery.py capture-publication --inputs /release/capture-inputs.json --output /release/prior
```

This uses the maintained publication HTTP reader, its 1 MiB index limit and a
60-second cooperative request bound. It retains the exact response in
`publication.raw.json`, validates the index, and saves the parsed
`publication.json`. Use the successful terminal's `result.prior` directly as
the later publication/readback `prior` pin. HTTP, size or parsing failures retain
a failed terminal; malformed response bytes remain available for diagnosis.
`--resume` returns only the verified historical capture. Use a new output
directory when a fresh current index is needed.

Complete later release inputs as their evidence becomes available:

```json
{
  "source": {"commit": "<exact commit>", "tree": "<exact tree>"},
  "image": {
    "qualification": {"path": "/release/image/qualification.json", "sha256": "<hash>"},
    "inspection": {"path": "/release/image/image-inspect.json", "sha256": "<hash>"},
    "build_inputs": {"path": "/release/image/build-inputs.sha256", "sha256": "<hash>"},
    "tools": "/checkout/deploy/cloudflare",
    "node": "/installed/bin/node", "docker": "/installed/bin/docker",
    "docker_host": "unix:///absolute/colima/docker.sock"
  },
  "serving": {
    "association": {"path": "/release/push/registry-association.json", "sha256": "<hash>"},
    "receipt": {"path": "/release/binding/consumer-receipt.json", "sha256": "<hash>"},
    "provider_selection": {"path": "/release/deployment/provider-selection.json", "sha256": "<hash>"},
    "rollback": {"path": "/release/rollback/rollback.json", "sha256": "<hash>"}
  },
  "publication": {
    "prior": {"path": "/release/rollback/publication.json", "sha256": "<hash>"},
    "protected_families": ["treasury-fiscal"],
    "env_file": "/existing/private/.env",
    "generation": {
      "directory": "/qualified/generation", "logical_id": "<exact logicalId>",
      "artifact_digest": "sha256:<exact digest>", "family": "<target family>",
      "tables": ["example"], "evidence_directories": ["/qualified/source-evidence/artifact"]
    }
  },
  "readback": {
    "prior": {"path": "/release/rollback/publication.json", "sha256": "<hash>"},
    "protected_families": ["treasury-fiscal"],
    "queries": [{
      "sql": "SELECT id FROM example ORDER BY id LIMIT 1", "columns": ["id"], "rows": [["literal"]],
      "publication": {"example": {
        "status": "managed_generation", "family": "<target family>", "artifact_digest": "sha256:<digest>"
      }}
    }]
  }
}
```

The `image` controls use the existing image qualification/inspection/build-list
formats. `serving` consumes the independently captured, accepted provider
selection: `status: pass`, actual `worker_version` and `container_version`,
`registry_image` and `receipt_sha256`. A configured image is not proof of actual
provider selection. The rollback control retains the compatible prior consumer,
image, receipt and Worker selection. Publication and readback share this check;
image push does not require the later `serving` fields.

Before `publish-data` reads write credentials or uploads anything, it performs
one bounded MCP `list_sources` check of actual installed code, selected receipt,
and compatibility of every declared FEC view. It retains mismatches and refuses
without a publication write; a successful provider selection alone is insufficient.
This operation supports independent family delivery while existing FEC inputs
remain selected. A target family referenced by the receipt's output membership,
view dependencies or evidence generations refuses explicitly. Coordinated FEC
input/receipt promotion belongs to the existing `publish_fec_release` owner;
this helper has no bypass for that separate operation. Read-only observation of
an uncertain earlier publication remains available.

Queries retain exact expected columns and rows, with one to eight queries and at
most 100 returned rows each. Each table must name its managed family/digest or
its FEC `release_compatibility` status, receipt hash, `sql_sha256`,
`evidence_generations`, `population` and `as_of` from the selected receipt. Include
the relevant existing FEC query when qualifying a new serving release. The server
continues to own SQL access restrictions. The client preserves the accepted
1 MiB response, 16 MiB retained output, 60-second request and 240-second total
bounds, including session cleanup; it does not restart expired sessions.

```sh
python deploy/cloudflare/local_delivery.py push-image --inputs /release/inputs.json --output /release/push
# Separately bind, deploy and accept actual provider selection using their existing owners.
python deploy/cloudflare/local_delivery.py publish-data --inputs /release/inputs.json --output /release/publication
python deploy/cloudflare/local_delivery.py readback --inputs /release/inputs.json --output /release/readback
```

For the existing FEC binder, assemble one build-evidence directory with the
build's `source-commit.txt`, `source-tree.txt`, `expected-source-commit.txt`,
`installed-consumer.json`, `image-inspect.json` and `build-inputs.sha256`, plus
the operation's `registry-manifest.json`, `pushed-image-inspect.json` and
`registry-association.json`. Local hardlinks preserve those exact files without
changing their originals. The operation retains the raw verified manifest,
checks a real local image inspection for the exact registry digest, and includes
the already checked `uv.lock` digest. It does not pull an image to manufacture
that association; missing local evidence refuses.

Use one fresh directory per operation. `--resume` validates the selected input
fields and all retained successful evidence, then returns the recorded result
without HTTP requests, Docker commands or publication writes. It does not assert
that an old result remains the live selection. Adding the later serving receipt
cannot invalidate a successful image push. Changed evidence or unsuccessful
results refuse resume. Do not evade that refusal with a new write directory.

An interrupted push or publication can have succeeded remotely. Retain its
original directory and use an explicit read-only operation in a fresh directory:

```sh
python deploy/cloudflare/local_delivery.py verify-image --inputs /release/inputs.json --from-output /release/push --output /release/image-observation
python deploy/cloudflare/local_delivery.py observe-publication --inputs /release/inputs.json --from-output /release/publication --output /release/publication-observation
```

Observation binds the original intent and never retries its write. Image recovery
uses Wrangler's short-lived pull credentials only in memory and a private Docker
config, which is removed on exit. If observation cannot establish the exact
candidate, stop for review; no automatic retry is supported. Publication still
uses full generation/evidence admission, verified immutable uploads and readback,
and current-parent/family compare-and-swap checks. The helper adds only the
explicit protected-family checks; unrelated historical coverage acceptance is
not a prerequisite for a new family's publication. Existing task evidence stays
retained; new deliveries change input data rather than script source.

## Private package and local reader checks

After committing the reviewed code and any necessary dependency-wheel adoption,
`local_package.py` builds the Regs wheel once, checks its package members against
that source, installs the frozen dependencies and wheel into a fresh private
runtime, and runs an installed consumer check. It uses offline `uv` commands and
records the lock, wheel, command times, logical output bytes and unchanged build
runtime file signatures. Logical file bytes are not a measured free-space gain.

```sh
python deploy/cloudflare/local_package.py --inputs /release/package-inputs.json --output /release/package
```

The input contains `source: {commit, tree}`, the existing build interpreter's
absolute `python` path, an explicit absolute `uv` executable path (for example
`/opt/homebrew/bin/uv`), and `check: {path, sha256}` for the reader expectations.
The helper resolves that executable and checks `uv --version` before building,
then records both in the terminal receipt. It does not select `uv` from `PATH`;
different installed versions can use different offline cache layouts.
The source must be clean and the output directory must be new. A failed output
retains its logs for diagnosis; inspect the failed step before another build.
Existing source fixtures and unchanged dependency wheels are reused.

`qualify_reader.py` takes `--expected <JSON path> --sha256 <exact file hash>`.
Its expectations contain:

- `generation: {directory, logicalId, artifactDigest}` for an existing generation.
- `queries: [{sql, columns, rows}]` with complete expected rows.
- `consumer` and `mcp_source_sha256` matching the installed serving code.
- Optional `inputs: [{path, sha256}]` for small retained fixture/control files.
- For an installed pipeline check, `pipeline: {module, argv}` invokes its normal
  CLI in process before querying the resulting generation. The generation
  directory must not already exist. Its generated
  `logicalId`/`artifactDigest` and consumer pins may be omitted because the
  package operation has already checked the wheel against the reviewed source.

Use `require_docs_absent: true` for the serving image. Run that image with the
existing read-only mounts, `--network none`, CPU/memory bounds and exact image
digest. The check also refuses Python socket attempts and verifies all loaded
Regs/Docs module origins belong to the installed runtime; the socket audit alone
does not isolate native-library networking. Image qualification reads the
already-built generation, while the private package check reuses a small retained
CLI fixture. Change paths and expected values in JSON rather than copying either
check script.
